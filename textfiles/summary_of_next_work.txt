  COMPLETED — RISK REGISTER (gap #20)
================================================================================

  Status: ✅ COMPLETE — implemented on branch phase-20-risk-register
  Branch: phase-20-risk-register (from main)
  Plan:   textfiles/risk_register_plan.txt

  Forward-looking, manually-maintained register of potential project risks
  (distinct from the auto-computed OVERDUE/AT RISK badges and from Issues,
  which are retrospective). Fields: risk description, probability x impact
  score (auto-computed 1-9 with Low/Medium/High level), mitigation plan,
  status (Open/Mitigated/Closed), date identified.

  UI: lives inside the existing Issues tab (renamed "Issues & Risks") with an
  All / Issues / Risks toggle; risk code in separate files. Admin/Staff CRUD,
  contractor read-only. ActivityLog on every change. High-level risks trigger
  an in-app notification to admins + the project's contractor (Low/Medium are
  visible only). No AI hook in this build (flagged for future:
  RecommendationEngine, MLR variable, Phase 10).

  Implemented across 4 phases (commits 98dfe41, 045d2af, 0f4fe4f, be9f64d):
  risks table + Risk model + factory, RiskController + 9 routes + ActivityLog,
  RiskReported notification (High-only, dedupe key), UI partial/modal/JS/CSS,
  15-feature RiskRegisterTest. Full suite: 351 tests passing.

  ENHANCEMENT (Aug 6 2026) — RISK → ISSUE CONVERSION, commits 5b69fee (Phase D)
  + 1896c1d (Phase E). Plan: textfiles/risk_to_issue_conversion_plan.txt.
  A Convert-to-Issue button (admin/staff) on Open/Mitigated risks opens a
  pre-filled, editable modal; confirming creates the issue, links both records
  (risk.converted_to_issue_id ↔ issue.source_risk_id), marks the risk Realized,
  transfers + relabels its evidence attachments to the issue (context 'risk' →
  'issue'), audits 'Convert Risk to Issue', and notifies admins + contractor.
  Risks gained an optional baseline month link + evidence attachments (parity
  with issues). Delete guards: Realized risks are blocked (422 "delete the
  issue first"); deleting a converted issue reverts its risk Realized → Open.
  Realized badge + "→ Issue #N" link in the risks table; "from Risk" badge in
  the issues table + edit modal. RiskRegisterTest extended to 30 tests; full
  suite now 367 passing.

  FOLLOW-UP POLISH (Aug 6 2026, uncommitted at 106f74d) — Risk Register:
    • Owner field removed from risks (guarded migration + all layers).
    • Add Risk modal: two-column layout, subtitle, larger score badge.
    • Baseline month auto-selects on Add Risk (getDefaultRiskBaseline).
    • Delete button hidden for Realized risks; server 422 guard remains.
    • No-reload refresh after issue delete (risk reverts in place).
    • Convert modal Evidence section: preview/remove/add attachments; removals

  ⭐ DONE (Aug 11-12, 2026) — AI MODULE: FORECAST RELIABILITY
  & PREDICTION CONFIDENCE REBASE (V2 PHASE 14)
  --------------------------------------------------------------------------------
  Status: ✅ COMPLETE — merged into main @ a45a156.
  Plan:  textfiles/forecast_reliability_confidence_plan.md
  Log:   textfiles/active_reference/ai_v2_phase14_forecast_reliability_progress_log.txt

  Why: R² is presented as "prediction confidence", but R² only measures how
  well the curve fits PAST data — it says nothing about whether the NEXT
  prediction is right. This is a well-known statistical trap (and a likely
  capstone defense question). The module already has the honest signal —
  prediction_history (predicted vs actual) — but confidence wording was
  never rebased onto it.

  Scope summary (all IMPLEMENTED):
    • NEW ForecastReliabilityService — weighted, explainable reliability
      score (0-100, High/Medium/Low) per forecast built from:
      backtest accuracy (prediction_history) 40% + real data sufficiency
      30% + forecast horizon 15% + cross-method agreement 15%, with hard
      floors (R² < 0.50 → Low) and an honesty cap (High requires evidence:
      ≥3 fulfilled predictions OR ≥6 real observations). Includes an additive
      next-month prediction RANGE (point ± margin) via a new nullable
      next_prediction_low/high/margin + next_prediction_range migration.
    • R² stays on screen but is relabeled "Curve Fit Quality (matches past
      data only)" — it keeps its legitimate model-selection job.
    • Applied to: next-month prediction card + Estimated Completion card
      (both show level + score/100 badge with a hover "why" tooltip).
    • Presenter/Blade prompt wording updated (AIExplanationService now
      prompts with the reliability block, not R²); all existing report keys
      kept (backward compatible).
