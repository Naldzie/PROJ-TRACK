  1. PHASE SUMMARY
================================================================================

  Objective:
    Replace all "R² as prediction confidence" wording with an honest,
    explainable FORECAST RELIABILITY score. R² measures how well the curve
    fits PAST data — it says nothing about whether the NEXT prediction is
    right (a well-known statistical trap and a likely capstone defense
    question). The prediction_history backtest already holds the honest
    signal; Phase 14 rebases the UI, presenter, and AI prompt onto it.

  Key Changes:
    • NEW ForecastReliabilityService — weighted, explainable reliability
      (0-100, High/Medium/Low) per forecast:
        Backtest accuracy (prediction_history)  40%
        Real data sufficiency                    30%
        Forecast horizon                         15%
        Cross-method agreement                   15%
      Hard floor: R² < 0.50 → Low. Honesty cap: High requires evidence
      (≥3 fulfilled predictions OR ≥6 real observations).
    • Next-month forecast gains an additive PREDICTION RANGE (point ± margin,
      lower/upper bounds + margin) via new nullable DB columns — the point
      stays a scalar, backward compatible.
    • R² is RELABELED "Curve Fit Quality (matches past data only)" — kept for
      its legitimate model-selection job, never shown as forecast trust.
    • Applied to: Next-Month Prediction card + Estimated Completion card.
    • AIExplanationService prompt now leads with the reliability block
      (label + /100 + the four factor scores) and demotes R² to a curve-fit
      note.

  Status: ✅ STEPS 0-7 COMPLETE — full suite 608 passed (2209 assertions).

================================================================================
  5. KEY DESIGN DECISIONS
================================================================================

   1. R² stays visible, demoted to curve-fit. R² still selects the model
      (SLR vs polynomial) and appears as "Curve Fit Quality (matches past
      data only)" — it never doubles as forecast confidence.

   2. Additive next-month RANGE. next_prediction remains the scalar point;
      the band is exposed via new nullable next_prediction_low/high/margin
      (+ range migration). All consumers that use next_prediction keep
      working unchanged.

   3. Reliability is explainable, not a black box. The blade's "why"
      tooltip lists the four weighted factors (score + human detail) so a
      reviewer/defense can see exactly why a forecast is Medium or Low.

   4. Completion reliability is independent of completion_confidence.
      completion_confidence (R²-relative) remains as a fallback key when
      reliability is null; the visible trust statement is the reliability
      badge.

   5. Polynomial completion methods guarded. A future-sanity guard removes
      polynomial from the completion-method set when its estimated date
      violates the "earliest plausible" bound, so method agreement reflects
      the methods actually considered. (Verified live: Project 5 agreement
      "All 2 methods agree — High, 15 days".)

   6. Supplement/aggregate honesty. Reliability factors carry a warning when
      the fit is built on cross-project synthetic data, and next-prediction
      reliability is penalized for the forecast-horizon factor.

   7. Prompt trust = reliability, not R². AIExplanationService now hands the
      model the reliability block (label + score + factors) and only notes R²
      as curve fit — so generated analysis text cannot overclaim from R².

   8. Render tests replace one-off browser passes. The multi-mode verification
      (Step 7) renders the real blade with real presenter output for every
      branch (completed / insufficient / SLR / polynomial / supplement),
      repeatable in CI instead of a manual date-simulator click-through.
