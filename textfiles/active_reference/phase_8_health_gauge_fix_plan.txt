  1. PROBLEM STATEMENTS
===============================================================================

  Problem A — Health Gauge Shows AT RISK When On Schedule
  --------------------------------------------------------
  The Project Health Gauge (and entire "Status" card in the AI Prediction
  tab) shows "AT RISK" / "Moderate Risk" even when a project is perfectly
  on schedule (progress gap = 0%, actual progress meets planned progress).

  Status: ✅ FIXED (committed: b3a0eb7)

  Problem B — Three-Method Completion Card Not Visible
  -----------------------------------------------------
  The "Completion Estimation Comparison (3 Methods)" card is not rendered
  when the polynomial solve method returns null. This happens in supplement
  mode (Phase 8 cross-project) when model selection chooses SLR over
  polynomial — the entire card hides even though Schedule-Aware and
  EAC_time may have valid estimates.

  Status: ✅ FIXED (committed: 3cb0fbd — merged to main)

  Problem C — Completion Confidence Inflated by Synthetic Data
  --------------------------------------------------------------
  The completion estimation methods (schedule-aware, polynomial, EAC_time)
  use combined observation count (real + synthetic) in their confidence
  calculation. A project with 1 real + 3 synthetic observations shows
  "Medium" confidence instead of "Low", overstating reliability.

  Status: ✅ FIXED (committed: 3cb0fbd — merged to main)

===============================================================================
  2. ROOT CAUSES
===============================================================================

  Problem B — Blade Gate Too Strict
  ----------------------------------
  Resources/views/.../ai-prediction.blade.php line 570:
    ($prediction['completion_multi']['methods']['polynomial'] ?? null) !== null

  The outer condition requires polynomial to have a valid result. If
  polynomial returns null (e.g., regression_method = 'slr' due to
  insufficient polynomial improvement), the entire card is hidden.

  Problem C — Confidence Uses Combined Count
  -------------------------------------------
  CompletionEstimationService::classifyConfidence() uses
  $analysis['observation_count'] which is the combined total (real +
  synthetic). The synthetic_points_count is not tracked in the analysis
  array — it's only in the prediction report's regression block.

  Schedule-aware and EAC_time methods primarily use real data (actual
  progress, actual month index, actual baselines) for their core
  calculation, so their estimates are reasonably reliable. But the
  confidence badge overstates reliability by counting synthetic points.

===============================================================================
  3. CHOSEN DIRECTION
===============================================================================

  Problem B — Show Card When ≥2 Methods Have Valid Data
  --------------------------------------------------------
  Change the gate condition from requiring polynomial !== null to
  requiring comparison.valid_count >= 2. Methods with null results
  already display "N/A — Could not estimate" in the template.

  Problem C — Pass Real Observation Count Through Pipeline
  ---------------------------------------------------------
  Inject synthetic_points_count into the analysis array before calling
  completion estimation methods. Then subtract it from observation_count
  before classifyConfidence(). This matches the same approach used for
  health_confidence.

  Fix C — Analysis Synthetic Count Pass-Through
  ------------------------------------------------
  File: app/Services/AI/AIPredictionService.php
  Location: generatePrediction(), around line 240, before estimateCompletion()

  After cross-project override and before completion estimation, inject
  synthetic_points_count from dataset statistics into analysis:

    $analysis['synthetic_points_count'] = $dataset['statistics']['synthetic_points_count'] ?? 0;

  File: app/Services/AI/CompletionEstimationService.php
  Location: classifyConfidence() — compute real obs count

  Before:

  And use $realObsCount in the confidence thresholds.
