===============================================================================
  WHAT THIS PLAN COVERS
===============================================================================

Fixing the S-Curve chart's actual line to show ALL individual progress
inspection records as data points on a continuous date axis, instead of
collapsing them to only the latest record per month.

===============================================================================
  THE PROBLEM
===============================================================================

The system allows multiple progress history records per month (e.g., a
re-inspection after a corrective action). However, the S-Curve chart's
actual line currently shows only ONE point per month — the latest record
by inspection_month_date.

Root cause: ProjectChartService::buildBaselineScheduleChartData()
    $progressHistory->where('month_label', $monthLabel)->last()
This filters to only the last record per month label. All earlier
inspection records for the same month are silently discarded.

===============================================================================
  CHOSEN DIRECTION
===============================================================================

Convert the chart X-axis from category-based (month labels) to
timestamp-based (linear scale with millisecond timestamps). This allows
individual data points to be positioned at their exact dates without
requiring a Chart.js date adapter library.

Data format change:
  - Planned datasets (Original Plan, Adjusted Plan): each point becomes
    { x: <planned_date_timestamp>, y: <planned_progress_percent> }
  - Actual dataset: each record becomes
    { x: <inspection_date_timestamp>, y: <actual_progress_percent> }
  - ALL progress history records included — no month_label filter

BUG FIX — Tooltip index misalignment (July 20, 2026):
  PROBLEM: After the multi-dot fix, `mode: 'index'` with datasets of
  different lengths (planned=24 entries, actual=48 entries) caused the
  tooltip to show mismatched data — e.g. hovering near Oct 2025 actual
  data (index 19 in actual_data) displayed Jun 2026's planned value
  (also index 19 in planned_data). The array index was no longer a valid
  common key across datasets.
  FIX: Changed interaction mode from `mode: 'index'` to
  `mode: 'nearest'` with `axis: 'x'`. Now finds the single nearest point
  by x-distance (timestamp proximity) across all datasets.
  TRADE-OFF: Tooltip now shows only one dataset's value at a time
  (whichever line is nearest to cursor), instead of all datasets
  simultaneously.

FUTURE ADDITION — Custom multi-dataset tooltip:
  To restore the ability to see Planned + Actual side-by-side in one
  tooltip, implement a custom tooltip plugin that finds the nearest
  data point in EACH dataset (by x-distance) and renders all values
  together. This would use Chart.js's `external` tooltip or a custom
  `onHover` handler with a positioned HTML overlay.
