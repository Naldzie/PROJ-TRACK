  1. PROBLEM STATEMENT
===============================================================================

  Current State
  -------------
  The Progress tab shows a single S-Curve chart with:
    • Original Plan (frozen) — solid blue line
    • Actual Progress — green dots connected by line
    • Adjusted Plan (extension) — orange line (when extensions exist)

  The AI Prediction module produces:
    • A short-term forecast (4-month predicted progress via regression)
    • Multi-method completion estimates (Polynomial, Schedule-Aware, EAC_time)

  What Is Missing
  ----------------
  1. No near-term forecast line on the S-Curve — PMU staff can't see the
     predicted trend for the next few months at a glance.
  2. No visual comparison of the two reliable completion estimates
     (Schedule-Aware vs EAC_time) on a chart — staff must read the
     multi-method completion card numbers on the AI Prediction tab.

  2. CHOSEN DIRECTION — TWO CHARTS, ONE TAB
===============================================================================

  Decision
  --------
  Add two visual enhancements to the Progress tab, both visible one after
  the other — no toggle needed:

  Chart 1 — Current Progress S-Curve (enhanced)
    • Retain all existing datasets (Original Plan, Actual, Adjusted Plan)
    • ADD: 4-month Polynomial Near-Term Forecast as a dashed purple line
    • Only shown when regression method is 'polynomial'
    • Labeled "Near-Term Forecast" — clarifies it's short-term only

  Chart 2 — Completion Forecast S-Curve (new, below Chart 1)
    • New Chart.js chart with:
      - Original Plan baseline (solid blue, same data as Chart 1)
      - Schedule-Aware shifted baseline (dashed purple)
      - EAC_time shifted baseline (dotted orange)
    • Shifted baselines = original planned curve displaced horizontally
      by each method's lag (estimated_completion_index - total_months)
    • Hidden entirely when insufficient data or project completed

  Why Not Just One Combined Chart?
  --------------------------------
  • Chart 1 focuses on CURRENT STATUS + NEAR-TERM outlook
  • Chart 2 focuses on LONG-TERM completion scenarios
  • Keeping them separate avoids visual clutter (5+ datasets on one chart)
  • Academic defensibility: two distinct analytical purposes

===============================================================================
  4. SHIFTED BASELINE ALGORITHM
===============================================================================

  Concept
  -------
  The planned S-curve represents the ideal schedule. If the project is
  running late by `lag` months, the same planned trajectory shifted
  right by `lag` months shows the realistic outlook.

  Formula
  -------
    total_planned_months = count(tick_timestamps)
    lag = estimated_completion_index - total_planned_months
    msPerMonth = 30.44 * 86400 * 1000  (average month in ms)

    for each point in frozen_planned_data:
        shifted_point.x = point.x + (lag * msPerMonth)
        shifted_point.y = point.y    (unchanged — same progress curve)

    Schedule-Aware shifted:  lag from completion_multi.methods.schedule_aware
    EAC_time shifted:        lag from completion_multi.methods.earned_schedule
