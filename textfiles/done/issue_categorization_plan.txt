===============================================================================
  PROBLEM
===============================================================================

Currently the RecommendationEngine counts unresolved issues:
  open_issue_count >= 3 → "Resolve open issues before they further
  impact progress"

This treats ALL issues identically. Three material-supply issues should
trigger a procurement recommendation. Three weather-delay issues should
trigger no action at all. The rule engine cannot distinguish them.

Additionally, the engine has no concept of issue aging — an issue that has
been open for 60 days is treated the same as one opened yesterday. There is
no resolution velocity tracking, so the system cannot tell if the team is
actively closing issues or letting them pile up.

===============================================================================
  GOAL
===============================================================================

Replace the single issue-count heuristic with categorized, severity-weighted,
and age-aware issue intelligence so that the RecommendationEngine can produce
targeted, context-sensitive recommendations.

===============================================================================
  SCOPE
===============================================================================

IN SCOPE (this session) — ✅ COMPLETE:
  • issue_type     — VARCHAR, nullable (categorizes the issue domain)
  • severity       — VARCHAR, nullable (Low / Medium / High / Critical)
  • resolved_at    — TIMESTAMP, nullable (auto-set when status→Resolved/Closed)
  • AI rule updates — type-aware, severity-weighted, age-aware rules

DEFERRED (future consideration):

    const TYPES = [
        'material', 'contractor', 'weather', 'design',
        'regulatory', 'financial', 'other',
    ];

    const SEVERITIES = ['Low', 'Medium', 'High', 'Critical'];

    // Cast resolved_at to a Carbon instance
    protected $casts = [
        'resolved_at' => 'datetime',
    ];

    // Scope: issues currently open or in progress (not yet resolved)
    public function scopeUnresolved($query)
    {
        return $query->whereIn('status', ['Open', 'In Progress']);
    }

    // Scope: issues that have been open beyond a given number of days
    public function scopeAging($query, $days = 30)
    {
        return $query->unresolved()
            ->where('created_at', '<=', now()->subDays($days));
    }

    // Scope: open issues of a specific type
    public function scopeOfType($query, $type)
    {
        return $query->where('issue_type', $type)->unresolved();
    }

    $data = $validated;

    // Auto-set resolved_at when status moves to Resolved or Closed
    if (in_array($data['status'], ['Resolved', 'Closed'])) {
        // Only set if not already resolved (preserve original resolution date)
        if (!in_array($issue->status, ['Resolved', 'Closed'])) {
            $data['resolved_at'] = now();
        }
    } elseif (in_array($issue->status, ['Resolved', 'Closed'])) {
        // Moving back to Open/In Progress — clear the resolution date
        $data['resolved_at'] = null;
    }

    $issue->update($data);

  SUMMARY OF NEW vs REPLACED RULES
===============================================================================

OLD (removed):
  • open_issue_count >= 3 → "Resolve open issues" (corrective, P3)

NEW (added):
  • issues_material >= 3        → "Review supply chain"          (corrective, P3)
  • issues_contractor >= 2      → "Address contractor perf"     (corrective, P2)
  • issues_design >= 2          → "Consider design review"      (corrective, P3)
  • issues_aging_count >= 2     → "Prioritize aging issues"     (corrective, P2)
  • issues_high_severity >= 1   → "Resolve high-severity"       (escalation, P1)
    AND risk High/Critical
  • issues_aging_count >= 5     → "Systemic escalation"         (escalation, P2)
  • low resolution velocity     → "Review issue management"     (monitoring,  P3)

===============================================================================
  IMPACT ON FUTURE AI RECOMMENDATIONS
===============================================================================

Issue categorization is the single most impactful data gap to close
because:

1. It's immediately usable by the rule engine — no AI required to see
   improvement in recommendation relevance.

2. Issue type + severity are structured categorical features — any ML
   model (regression, random forest, future neural network) consumes
   them natively as one-hot encoded dimensions.

3. resolved_at enables velocity and aging metrics — turning static
   issue snapshots into trend analysis.

4. It creates the foundation for outcome tracking: if an issue is
   closed and progress improves afterward, that's a signal an AI can
   learn from.

Without categorization, all issue-related recommendations are
noise. With it, they become the most actionable recs in the system.
