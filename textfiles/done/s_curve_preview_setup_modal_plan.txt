================================================================================
  WHAT THIS PLAN COVERS
================================================================================

B9 Item 3 from the main plan: adding a live S-Curve chart preview inside the
Set Up Baseline modal, so the user can see the cumulative progress curve build
in real-time as months are added during initial baseline setup.

This involves:
  • Extracting the existing Chart.js chart from progress.blade.php into a
    reusable component (Blade partial + JS function).
  • Redesigning the Set Up Baseline modal layout to accommodate the chart
    alongside the existing add-month form and month list.
  • Wiring the chart to the local setupLocalMonths array so it updates live
    on each "Add Month" click (no server calls for preview).

================================================================================
  PREREQUISITE / DEPENDENCY
================================================================================

Chart.js is already loaded via CDN on the project detail page. Since the Set Up
Baseline modal exists on the same page, no additional library loading is needed.

NO dependency on B3.1 (create-project modal integration) — this work is purely
within the existing project-detail-page usage of the Set Up Baseline modal.

================================================================================
  DECISION LOG
================================================================================

Decision 1 — Layout approach
  Context: The Set Up Baseline modal needs to accommodate a chart but space
  is limited.
  Options considered: Three-column (rejected), Top form+chart + bottom list
  (Option 2), Tabbed (Option 4).
  Decision: Start with Option 2 (two-column top: form | chart, full-width
  month list below). Fall back to Option 4 (tabbed) if Option 2 doesn't
  work well in testing.
  Rationale: Best balance of chart visibility + workflow continuity.

Decision 2 — Chart component extraction approach
  Context: The existing chart is hardcoded to the progress tab. Need
  reusability without duplication.
  Options considered: (a) inline chart function in modal JS (duplication),
  (b) shared Blade partial + JS function.
  Decision: Shared Blade partial + JS function. Both progress tab and modal
  consume the same component.
  Rationale: Follows existing pattern (baseline-schedule-utils.js for shared
  JS utilities). Prevents maintenance burden of two chart implementations.

Decision 3 — Chart update strategy
  Context: Chart must re-render on each "Add Month" / remove-month action.
  Options considered: (a) destroy + recreate on each change, (b) use
  Chart.js's built-in data update API (chart.data.labels = ..., chart.update()).
  Decision: Use Chart.js data update API (option b).
  Rationale: More performant, avoids flicker, no risk of orphaned canvas
  elements.

CONTEXT: Continued B9 Item 3 after Phase 1. Redesigned the Set Up Baseline modal

preview to update on every add/remove month action.

WHAT WAS BUILT:

     — New layout:
         TOP ROW (grid 1fr 1fr): Add Month form (left) | S-Curve preview (right)
         BOTTOM ROW (full-width): Progress bar + Month list (max-height 220px)

     — Chart included via reusable @include('components._s_curve_chart', ...)
       from Phase 1 with chartId='setupSCurve', height=300px.

  ✅ MODIFY: baseline-schedule-setup-modal.js — Chart lifecycle management
     — NEW variable: setupSCurveChart (separate from progress tab's scurveChart).
     — NEW function: updateSetupSCurvePreview()
         - 0 months → destroys chart, shows placeholder text.
         - 1+ months with existing chart → updates labels/datasets via
           Chart.js data API (chart.data.labels = ..., chart.update()).
         - 1+ months first time → creates canvas element, calls
           createSCurveChart() from the shared Phase 1 function.
     — Called from:
         - openSetupBaselineModal() — resets to empty placeholder.
         - addSetupBaselineMonth() — updates after pushing new month.
         - removeSetupBaselineMonth() — updates after splicing month.
     — Cleanup on modal hidden (hidden.bs.modal) — destroys chart instance to
       prevent memory leaks across multiple opens in the same page session.

DESIGN DECISIONS:
  - Decision 3 (chart update strategy): Used Chart.js data API (chart.update())
    instead of destroy/recreate. Only 0→1 months creates the chart; all
    subsequent updates reuse the existing instance. Flicker-free.
  - Modal height: chart at 300px, month list at max-height 220px. Together with
    the form, the modal scrolls naturally for long lists rather than cramming.

BUG FIXES FOUND DURING TESTING (July 13, 2026):
  ✅ BUG #1: S-Curve preview only showed the first month's point; subsequent
     add/remove operations did not update the chart.
     Root cause: updateSetupSCurvePreview() tried to set
     dataset[1].data (Actual dataset), but createSCurveChart() only creates
     the Actual dataset when at least one value is non-null. During setup all
     actual values are null (no actuals exist), so dataset[1] was never
     created. The error silently aborted chart.update(), leaving the chart
     frozen at the first render.
     Fix: removed the datasets[1] assignment. The modal chart only needs the
     Planned dataset (datasets[0]) — there are no actuals to plot during setup.

  ✅ BUG #2: Cancel button closed modal instantly, so the incomplete warning
     was never visible to the user (it flashed and disappeared).
     Root cause: the Cancel button had data-bs-dismiss="modal" which fires
     immediately after onclick, closing the modal before the warning could
     be seen.
     Fix: removed data-bs-dismiss from the Cancel button. Rewrote
     onSetupBaselineCancel() with a two-click pattern:
       - Click 1 (incomplete): shows warning in footer, modal stays open.
       - Click 2 (or if complete): closes modal.
       - Uses the warning display state as the confirmation flag.
     LATER REPLACED (see Phase 4 session below): the inline warning was
     replaced with the reusable delete-confirmation-modal for a more
     prominent and standard UX.

TESTING (user-confirmed, July 13, 2026):
  Core functionality:
  - ✅ Open Setup modal → chart placeholder visible on the right.
  - ✅ Add 1 month (25%) → chart shows 1 point, list shows 1 row, bar at 25%.
  - ✅ Add 2nd month (55%) → chart updates with 2nd connected point.

  - ✅ Cancel before 100% → confirmation modal shown, modal stays open.
  - ✅ Re-open after Cancel → fresh state, no stale chart.
  - ✅ Done at 100% → saves, page reloads on Baseline tab.
  Chart-specific (pending — layout/design issues to be discussed first)
