CONTEXT & SCOPE
===============================================================================

Phases 1–5 complete. The AI prediction pipeline (regression, forecast,
baseline comparison, risk assessment) is fully integrated into the Project
Detail page with real data flowing to the Blade.

Phase 6 adds an AI API (Gemini recommended) to replace the static template-
based analysis text with natural-language explanations. The AI receives the
regression data + project context and writes a professional analysis.

CRITICAL SCOPE NOTE — Analysis Text ONLY:
─────────────────────────────────────────
Phase 6 only improves the analysis TEXT (the narrative explanation). It does
NOT generate recommendations or mitigations. Recommendations remain as
static placeholders from the presenter.

Reasons recommendations are deferred to Phase 7:
- The regression module only sees progress% vs time — it has zero awareness of
  contractor performance, budget status, activity-level breakdown, or other
  project-specific factors that would be needed for meaningful mitigation advice
- Feeding just R² and variance to an AI would produce better-worded but still
  generic recommendations — no real value over the current placeholders
- Phase 7 can be implemented later when more contextual data is integrated

===============================================================================
KEY DECISIONS & SYSTEM CONTEXT
===============================================================================

AI PROVIDER: Google Gemini API (Recommended for V1)
  • Free tier: 60 requests/min, 1,500/day — more than enough for manual trigger
  • Setup: Get free API key from Google AI Studio, no billing needed
  • Fallback: Static template text if API call fails
  • Architecture is provider-agnostic — swapping to OpenAI or local later
    requires changing only the HTTP call inside AIExplanationService

DATABASE: ai_solutions table (already in ERD, not yet implemented)
  • Stores each generated analysis with regression snapshot
  • Each "Regenerate" creates a NEW row (history preserved)
  • Page load reads latest row from DB — NO API call on page load
  • Manual trigger only — user clicks "Regenerate Analysis" button

PROJECT DATA LIMITATIONS (relevant for AI context):
  • Budget is a contract total only — no spending tracking needed per client
  • Contractor performance — not yet implemented (not user's scope)
  • Location — all projects within university campus (no meaningful variance)
  • Issues — simple CRUD, manually typed (available for AI context but basic)
  • Activities — checklist-based, grouped by month, no individual progress %
  • Weather/seasonal — not in current scope

PHASE 6.2 — AIExplanationService
-------------------------------------------------------------------------------
Create the core service that sends regression data to the AI.

FILES TO CREATE:
  app/Services/AI/AIExplanationService.php

SERVICE METHODS:
  generate(Project $project): string
    • Entry point. Called by controller when user clicks regenerate.
    • Builds prompt from project data + regression data.
    • Calls Gemini API.
    • Returns analysis text (saves to DB internally).

  buildPrompt(Project $project, array $prediction): string
    • Constructs a structured prompt with project context and regression data.
    • Includes issues if available.

  callGemini(string $prompt): string
    • HTTP POST to Gemini API with API key.
    • Returns the generated text.
    • Handles timeout, errors → returns empty string (triggers fallback).

  saveAnalysis(Project $project, string $text, array $snapshot): AiSolution
    • Creates new AiSolution record.

  getLatest(Project $project): ?AiSolution
    • Query latest AiSolution for project.
    • Used by presenter on page load.

ENVIRONMENT CONFIG (.env):
  AI_API_KEY=your_gemini_api_key_here
  AI_MODEL=gemini-1.5-flash

CONFIG (config/services.php):
  'gemini' => [
      'key' => env('AI_API_KEY'),
      'model' => env('AI_MODEL', 'gemini-1.5-flash'),
  ],

PROMPT STRUCTURE (draft):
  "You are a project management analyst. Given the following project data,
  write a concise 2-3 paragraph analysis of the project's current status.
  ...
  Do NOT make specific recommendations — just analyze the current trajectory
  and its implications."

FALLBACK BEHAVIOR:
  If API call fails (timeout, network error, invalid key):
  → Return empty string
  → Presenter falls back to the static generateAnalysisText() template
  → Analysis text remains unchanged in the database

    function regenerateAnalysis(projectId) {
        const btn = document.getElementById('regenerate-btn');
        const status = document.getElementById('regenerate-status');
        const textDiv = document.getElementById('analysis-text');
        btn.disabled = true;
        status.style.display = 'inline';
        
        fetch(`/admin/projects/${projectId}/regenerate-analysis`, { method: 'POST' })
            .then(r => r.json())
            .then(data => {
                textDiv.innerText = data.analysis_text;
                status.innerText = 'Generated: ' + data.generated_at;
                btn.disabled = false;
            })
            .catch(() => {
                status.innerText = 'Failed to regenerate. Try again.';
                btn.disabled = false;
            });
    }
