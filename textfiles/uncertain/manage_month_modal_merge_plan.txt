===============================================================================
  PROBLEM
===============================================================================

  Currently each month card has two separate buttons that open two separate
  modals for related work:

    "Edit" button   → add_month_target_modal.blade.php (edit mode)
                      — changes planned_progress_percent, planned_date, description
                      — activities section is hidden: "Activities are managed
                        separately via the 'Manage' button."

    "Manage" button → manage_activities_modal.blade.php
                      — add/delete activities for the month
                      — no access to target fields

  The user must open two modals sequentially to do related work. Additionally,
  when "Edit" is hidden (no extension or has progress), the target info is
  inaccessible from the activities modal even in read-only form.

===============================================================================
  CHOSEN DIRECTION
===============================================================================

  Replace both "Edit" and "Manage" buttons with a single "Manage Month"
  button that opens one merged modal containing:

    1. Target information section (read-only or editable depending on state)
    2. Activities management section (always interactive)

  The modal determines which mode to use based on the project state:

    Mode "edit"
      — Available when: extension_count > 0 AND no progress recorded
      — Target fields: editable
      — Save button: PATCH target + description
      — Activities: inline add/delete via AJAX (live CRUD, same as current
        manage_activities_modal.js)

    Mode "activities-only"
      — Available when: no extension OR has progress
      — Target fields: displayed as read-only summary (frozen/locked)
      — No save button for target (just a Close/Done button)
      — Activities: inline add/delete via AJAX (same as above)

===============================================================================
  MODAL BEHAVIOR
===============================================================================

  openManageMonthModal(scheduleId, monthLabel, plannedDate,
                       plannedProgressPercent, description, mode)

    scheduleId            — baseline schedule row ID (null for activities-only)
    monthLabel            — e.g. "2026-01"
    plannedDate           — e.g. "2026-01-31"
    plannedProgressPercent — current target %
    description           — current description text
    mode                  — "edit" or "activities-only"

  Mode "edit":
    — Target inputs enabled, "Save Changes" button visible
    — saveManageMonthTarget() sends PATCH to /baseline-schedules/{id}
    — On success: close modal, reload page (follows existing pattern)

  Mode "activities-only":
    — Target inputs disabled (readonly/display only), no save button
      → button text is "Close", onclick = close modal only
    — Activities section always interactive in both modes

  Activities (both modes):
    — on open: fetchActivities(monthLabel) → render list with delete buttons
    — addManageMonthActivity() → POST → re-render list
    — deleteManageMonthActivity(id) → DELETE → re-render list
    — After add/delete: call reloadInlineActivities(monthLabel) to sync card
