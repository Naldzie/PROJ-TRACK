================================================================================
  WHAT THIS PLAN COVERS
================================================================================

Redesigning the S-Curve chart's planned/extension lines to use the real
database columns now that Part B (baseline schedule redesign) is complete:

  • FROZEN PLAN LINE → plots `original_planned_progress_percent`
    (the original baseline, never changes after initial setup)

  • ADJUSTED PLAN LINE → plots `planned_progress_percent`
    (the live/adjustable plan that includes post-extension months/edits)

  • Remove the old calculated projection lines (`extension_data` /
    `extension_data_alt`) and the Current/Alternative toggle — they were
    temporary workarounds that are now superseded by real data.

================================================================================
  WHY THIS CHANGE NOW
================================================================================

Before Part B was implemented, the system had no way to store an adjusted
plan post-extension. The chart papered over this gap with two calculated
projection lines (linear from last-actual-to-deadline, and linear from
start-date-to-deadline), toggled via Current/Alternative buttons.

Part B added:
  • `original_planned_progress_percent` column (frozen — the original plan)
  • Post-extension months can be added/edited in `planned_progress_percent`
  • Two-column approach mirrors the existing `projects.planned_end_date` /
    `projects.original_planned_end_date` pattern

Now the chart can show REAL data instead of calculated projections.

     Data source: original_planned_progress_percent.
     Null for extension-only months (where original is NULL) — line has
     a gap at those points (spanGaps = false).

  2. "Actual Progress" (green, #10b981) — shown only if actual data exists.
     Unchanged from current behavior.

  3. "Adjusted Plan" (amber, #f59e0b) — shown ONLY when the project has

     Data source: planned_progress_percent (the live column).

     spanGaps = true (no gaps since planned_progress_percent is always
     set for all rows).

================================================================================
  EDGE CASES / OPEN QUESTIONS
================================================================================

  Q: What if extension_count > 0 but planned_progress_percent has NOT been
     adjusted yet (identical to original_planned_progress_percent)?
  A: Adjusted Plan line should still show (it IS the current effective
     plan). It will overlap the Original Plan line visually. This is correct
     and expected — it shows the user that no adjustments have been made yet.

  Q: What about the monthly_summary table's planned_percent field?
  A: Unchanged — it shows planned_progress_percent (the current adjusted
     plan). The summary compares actual progress against the CURRENT plan,
     which is the correct comparison for ongoing projects.

  Q: Should the variance trend chart be updated too?
  A: No — variance trend reads planned_progress_percent from progress
     history records (the planned value that was current AT THE TIME of
     recording). This is independent of the baseline table's current values.

  Q: What happens to the old projection methods (calculateExtensionBaseline,
     calculateExtensionFromStartDate, extendChartForExtensionCompletion)?
  A: They are kept in the file but no longer called. They can be deleted
     in a future cleanup pass after the new behavior is confirmed stable.
