## 1. Problem Statement

When creating a new project, users currently have two options to build the baseline S-curve plan:

1. **Upload an S-curve document** (Excel `.xlsx` or PDF) for the system to parse
2. **Manually add every month target** one-by-one, entering the month label, target date, and cumulative percentage for each

When:
- The uploaded document cannot be parsed by the system
- The user does not have an S-curve document yet
- The project is small and does not warrant a full scheduling document

...the user is forced to manually add every single month and its cumulative percentage. For a 24-month project, that is 24 separate form submissions. This is tedious, error-prone, and unnecessary since the system already knows the project's planned start and end dates.

### Important Clarification: This Is NOT Activity-Level Scheduling

Enterprise tools like Procore, Primavera P6, and MS Project generate S-curves from **detailed activity scheduling** (Work Breakdown Structure with individual tasks, start/end dates, and budget per activity). That is a full scheduling tool — overkill for our use case.

Our feature is fundamentally different. It generates **only the planned baseline line** (the cumulative % curve) from the project's start and end dates. This is the same approach used by standalone S-curve calculators (Ensign Software, Arkan CS), except we build it directly into the app.

The user does NOT need to:
- Define individual activities or work packages
- Assign budgets to tasks
- Create a full project schedule

The user ONLY needs:
- A project with a planned start date and planned end date (already required fields)
- The system generates the monthly cumulative % targets automatically

After generation, the user can then add activities manually via "Manage Month" if they want more detail — but the monthly targets already exist as the tracking baseline. The auto-generate simply saves the user from typing 12-36+ month entries by hand.

This feature is for **newly approved projects with no real progress yet** — the project is just starting, and the user needs a baseline plan to track against. The generated curve is the **planned line only** (not the actual line), and serves as the target that future progress will be measured against.

## 2. Objective

Add a **one-click "Auto-Generate S-Curve"** feature inside the baseline setup modal that automatically creates a complete set of monthly baseline targets based solely on the project's planned start date and planned end date, using an industry-standard S-curve mathematical model. This generates the **planned baseline line only** — no activities, no cost loading, just the cumulative % by month.

The generated plan should:

- Produce the correct number of months based on the date range (e.g., Jan 2026 to Dec 2026 = 12 months; Mar 2025 to Aug 2027 = 30 months)
- Follow a realistic construction S-curve distribution (slow start, peak middle, slow finish)
- Allow the user to select the curve shape (symmetric, front-loaded, back-loaded)
- Be fully editable after generation (user can edit any month's percentage, add/remove months, and add activities via "Manage Month")

### Relationship to File Upload Feature

This feature does NOT replace the existing S-curve file upload (Excel/PDF import). The file upload is the primary flow and extracts both the monthly targets AND activities from the contractor's schedule document. Auto-generate is a fallback assistance for specific scenarios.

**Priority hierarchy:**

| Priority | Scenario | Result |
|----------|----------|--------|
| 1 (Best) | User uploads S-curve file | System parses both monthly targets AND activities |
| 2 (Fallback) | File upload fails or file is unreadable | Auto-generate fills in the curve; user adds activities manually |
| 3 (No file) | User has no file to upload | Auto-generate fills in the curve; user adds activities manually |

**Behavior in the UI:**
- The auto-generate section appears ONLY when the modal is empty (no months loaded)
- If a file import already populated the months, the auto-generate section is hidden — it will NOT overwrite imported data
- The auto-generate button is always available as a fallback, even after a failed import
- Activities are NEVER generated by auto-generate — they always come from file import or manual "Manage Month"
- Work in both entry points: the project detail "Set Up Baseline" button AND the create-project wizard

## 3. Research: S-Curve Mathematical Models

### 3.1 Industry-Standard Models

Six primary mathematical models are used in construction PM software for S-curve generation:

#### Model A: Logistic / Sigmoid Function
```
y(t) = L / (1 + e^(-k * (t - t₀)))
```
- `L` = maximum (100%), `k` = steepness, `t₀` = inflection point (typically 0.5)
- Requires rescaling to ensure exact 0% and 100% bounds
- Used by: academic tools, Excel SCURVE Lambda
- Pros: Well-studied, flexible steepness
- Cons: Exponential computation, needs rescaling

#### Model B: Hermite Smoothstep (DHSS / Kenley-Wilson) ← RECOMMENDED
```
C(t) = 3t² - 2t³
```
- Where `t` = normalized time (0 to 1 across project duration)
- With skew: `C(t) = 3x² - 2x³` where `x = pow(t, 1/skew)`
- Used by: Ensign Software, UK construction industry (DHSS formula), Kenley & Wilson (1986/2003)
- Pros: Simplest implementation (no exponentials), guaranteed C(0)=0 and C(1)=1, zero slope at both ends, supports front/back loading via single parameter
- Cons: Less theoretically grounded than logistic

#### Model C: Cubic Polynomial (Peer / Chao-Chien)
```
y(t) = a₁t³ + a₂t² + a₃t
```
- Empirically fitted from analysis of 101 construction projects (Chao & Chien, 2009)
- Coefficients vary by project type:
  - Residential: `y = -1.04t³ + 1.72t² + 0.32t` (R² = 0.98)
  - Commercial: `y = -0.77t³ + 1.56t² + 0.21t` (R² = 0.95)
  - All buildings average: `y = -0.67t³ + 1.36t² + 0.31t` (R² = 0.92)
- Pros: Empirically validated with real project data
- Cons: Coefficients vary by project type; less generalizable

#### Model D: Modified Logistics (Russell, 2005)
```
y(t) = Y∞ / (1 + δ·e^(-γ·t))
```
- Pros: Three-parameter control
- Cons: Complex parameter fitting

#### Model E: Lara-Dinsmore
```
cumulative% = 1 - (1 - (n/N)^LOG(I))^S
```
- `I` = asymmetry (30-70, default 50 for symmetric), `S` = kurtosis (1.5-2.5)
- Pros: Simple 2-parameter control
- Cons: Less academic validation

#### Model F: Beta Distribution (Kim & Reinschmidt, 2007)
- Uses regularized incomplete beta function
- Pros: Best statistical fit to real data
- Cons: Complex to implement in JavaScript

### 3.2 Typical Construction S-Curve Distribution

Real-world data from analysis of 345 construction projects (12-month duration):

| Month | Monthly % | Cumulative % | Phase |
|-------|-----------|-------------|-------|
| 1     | 6.04%     | 6.04%       | Initiation (mobilization) |
| 2     | 9.60%     | 15.64%      | Initiation |
| 3     | 11.88%    | 27.52%      | Growth (foundations) |
| 4     | **13.12%** | **40.64%** | **Growth — PEAK** |
| 5     | 12.06%    | 52.70%      | Maturity |
| 6     | 10.71%    | 63.41%      | Maturity |
| 7     | 9.81%     | 73.22%      | Maturity |
| 8     | 7.88%     | 81.10%      | Decline |
| 9     | 6.53%     | 87.63%      | Decline |
| 10    | 4.89%     | 92.52%      | Decline |
| 11    | 3.93%     | 96.45%      | Decline (finishes) |
| 12    | 3.53%     | 99.98%      | Decline (handover) |

**Key finding:** The 4th month (of 12) always shows the highest earned value regardless of contractor type or project size.

### 3.3 Four Phases of a Construction S-Curve

```
Phase 1: INITIATION (0-15% of duration, ~5% of value)
  Site setup, mobilization, temporary works
  → Slow spending, flat curve

Phase 2: GROWTH (15-45% of duration, ~35% of value)
  Substructure, early superstructure
  → Curve steepens, accelerating spend

Phase 3: MATURITY (45-75% of duration, ~45% of value)
  Main superstructure, MEP, building envelope
  → Steepest part of S-curve, peak monthly spend

Phase 4: DECLINE (75-100% of duration, ~15% of value)
  Finishes, commissioning, snagging, handover
  → Curve flattens, diminishing monthly spend
```

### 3.4 How Other Systems Handle This

| System | Approach | Our Distinction |
|--------|----------|----------------|
| **Procore** | Requires WBS with individual activities; spreads cost linearly per activity. Does NOT auto-generate from dates alone. | We only generate the planned % line, not activities. |
| **Primavera P6** | Same as Procore — requires detailed activity scheduling. Supports early-start and late-start "banana curves". | We don't do activity-level scheduling or banana curves. |
| **MS Project** | Tasks with start/finish/cost → baseline → cumulative costs form S-curve. Does not auto-generate. | We auto-generate from dates alone; no task setup required. |
| **Ensign Software** | Calculator with Hermite smoothstep; user provides start/end dates + total value + loading type. **Closest to our use case.** | Same approach, but integrated into our app instead of external tool. |
| **Arkan CS** | Free web tool for early-start, late-start, and bell curve distributions. Input: dates + total value. | Similar standalone tool; we integrate directly. |
| **Excel SCURVE Lambda** | Uses `NETWORKDAYS.INTL` for work-day calculation; Hermite-based. | We use calendar months instead of work days for simplicity. |

**Key distinction:** Enterprise tools (Procore, P6, MS Project) generate S-curves as a byproduct of detailed activity scheduling — they require a full WBS to produce any curve at all. Standalone calculators (Ensign, Arkan) generate the curve shape from dates + value alone — no activities needed. Our feature follows the standalone calculator approach: **generate the planned baseline line from dates, activities are optional and added later.**

### 3.5 Why Hermite Smoothstep Is the Best Choice

1. **Computationally trivial:** `3t² - 2t³` — no exponentials, no logarithms, no special functions
2. **Guaranteed boundary behavior:** C(0) = 0, C(1) = 1, slope = 0 at both endpoints
3. **Single parameter for shape:** `skew` controls front/symmetric/back loading
4. **Industry proven:** Used by Ensign Software and the UK DHSS (Department of Health and Social Security) formula since 1986
5. **Matches real data:** Produces distributions that closely match the 345-project empirical data (peak at ~33-40% through the project)
6. **Easy to explain:** "A smooth transition from 0% to 100% that starts slow, speeds up in the middle, and slows down at the end"

### 4.2 Step 1: Core Generator Function

**File:** `public/js/admin/projects/scurve-import-core.js`

Add a new exported function `generateAutoSCurve`:

**Inputs:**
- `startDate` — project planned start date (`YYYY-MM-DD` string)
- `endDate` — project planned end date (`YYYY-MM-DD` string)
- `options.loading` — `'symmetric'` | `'front'` | `'back'` (default: `'symmetric'`)

**Algorithm:**
1. Parse start and end dates
2. Calculate `totalMonths = (endYear - startYear) * 12 + (endMonth - startMonth) + 1`
3. Map skew values: `symmetric → 1.0`, `front → 0.7`, `back → 1.4`
4. For each month `m` from 1 to `totalMonths`:
   - `t_end = m / totalMonths` (normalized time at end of this month)
   - `t_start = (m - 1) / totalMonths` (normalized time at start of this month)
   - Apply skew to both: `x_end = pow(t_end, 1/skew)`, `x_start = pow(t_start, 1/skew)`
   - Compute cumulative: `C_end = 3 * x_end² - 2 * x_end³`, `C_start = 3 * x_start² - 2 * x_start³`
   - `monthlyPercent = C_end - C_start`
   - `cumulativePercent = C_end * 100` (rounded to 2 decimal places)
   - `month_label = YYYY-MM` format from start date + (m-1) months
   - `planned_date = 15th of that month` (consistent with existing `generateAutoDistribution()` convention)
5. Force the last month to exactly `100.00%`
6. Clamp: ensure all cumulative percentages are strictly increasing (no duplicates or decreases)
7. Return array in the same shape as `normalizeSCurveMonths()` output:
   ```javascript
   [{ month_label, planned_date, planned_progress_percent, description: '', activities: [] }]
   ```

**Edge cases:**
- If start > end: return empty array
- If totalMonths < 2: return single month at 100%
- If dates are missing: return empty array

#### 3a. Show/Hide Logic

Modify the existing flow in `openSetupBaselineModal()` (line 135) and `renderSetupMonthList()` to control visibility of `#setupAutoGenSection`:

- **Show** when: `setupLocalMonths.length === 0` AND both `startDate` and `endDate` are available from `getSetupDateBounds()`
- **Hide** when: months exist, or dates are missing

```javascript
function updateAutoGenVisibility() {
    var section = document.getElementById('setupAutoGenSection');
    if (!section) return;
    var bounds = getSetupDateBounds();
    var hasDates = bounds.min && bounds.max;
    var isEmpty = setupLocalMonths.length === 0;
    section.style.display = (hasDates && isEmpty) ? 'block' : 'none';
}
```

Call `updateAutoGenVisibility()` from:
- `openSetupBaselineModal()` — after resetting state
- `renderSetupMonthList()` — after rendering (so it hides once months are added)
- `autoGenerateSCurve()` — after generation (to hide the section)

#### 3b. New Function: `autoGenerateSCurve()`

```javascript
function autoGenerateSCurve() {
    var bounds = getSetupDateBounds();
    if (!bounds.min || !bounds.max) {
        showToast('Please set project start and end dates first.', 'error');
        return;
    }

    var curveType = document.getElementById('setupAutoGenCurveType').value || 'symmetric';
    var months = window.scurveImportCore.generateAutoSCurve(bounds.min, bounds.max, {
        loading: curveType
    });

    if (!months || months.length === 0) {
        showToast('Could not generate S-curve. Check that start date is before end date.', 'error');
        return;
    }

    // Confirm if months already exist (shouldn't happen since section is hidden, but safety check)
    if (setupLocalMonths.length > 0) {
        var ok = confirm('This will replace the current ' + setupLocalMonths.length + ' months. Continue?');
        if (!ok) return;
    }

    // Populate local months
    setupLocalMonths = months;
    setupCurrentMaxPercent = months.reduce(function (max, m) {
        return Math.max(max, parseFloat(m.planned_progress_percent) || 0);
    }, 0);
    setupEditingIndex = null;

    // Re-render
    resetSetupForm();
    renderSetupMonthList(setupLocalMonths);
    updateSetupProgress(setupLocalMonths);
    updateSetupSCurvePreview();
    updateAutoGenVisibility();

    showToast('Generated ' + months.length + ' monthly targets using ' + curveType + ' S-curve.', 'success');
}
```
